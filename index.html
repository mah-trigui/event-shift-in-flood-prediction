When Train and Test Are Different Events, Feature Importance Changes

Flood prediction across events using physically invariant spatial structure

View Repository Explore Method

Overview

This project predicts flood extent in Malawi under an event-shift setting: training data comes from one flood event, while predictions are required for a different later event.

That changes the modeling problem. The main question is no longer just which algorithm fits best, but which features are stable enough to transfer across floods with different rainfall patterns and storm behavior.

The feature strategy therefore prioritized physical landscape invariants over event-specific fingerprints.

Architecture

The Core Idea

When train and test come from different events, historical signal is not equally transferable.

Rainfall triggers flooding, but terrain and soil structure control where water can accumulate, drain, or infiltrate. Those mechanisms are more stable across events than the exact rainfall signature of a single past storm.

Under event shift, favor physically invariant structure over event-specific detail.

Feature families used

Terrain derivatives

Slope, aspect, roughness, terrain position, and flow direction were derived from elevation to capture water movement and accumulation.

Soil properties

Drainage, parent material, erosion, and related soil variables were used as infiltration and pooling controls.

Event rainfall

Rainfall remained important, but some early weak-signal weekly columns were dropped to avoid over-weighting event-specific noise.

Target-aware diagnostics

Auxiliary zero-inflation targets were created to better understand a highly sparse flood-fraction response.

Selected implementation details

  • terrain raster built from X / Y / elevation fields
  • slope, aspect, TPI, TRI, roughness, flow direction, and hillshade extracted back to grid squares
  • soil categoricals cleaned and harmonized into reusable factor levels
  • zero-inflation proxies created for exploratory decomposition of flood severity
  • predictions clipped to the valid target range [0, 1]

2. Zero-inflation auxiliary targets

all$bin[train_rows & all$target == 0] <- "0"
all$bin[train_rows & all$target > 0] <- "1"

all$zero[train_rows & all$target == 0] <- "0"
all$zero[train_rows & all$target > 0 & all$target < 0.6] <- "1"
all$zero[train_rows & all$target >= 0.6] <- "2"

all <- all[, !names(all) %in% drop_vars, with = FALSE]

clip_predictions <- function(x) pmax(0, pmin(1, x))

Why this matters

  • event shift is different from ordinary row-wise generalization
  • physically stable features are often more transferable than historical event fingerprints
  • feature selection should reflect the kind of distribution shift expected at deployment time
  • the principle generalizes to wildfire, drought, storm, and other environmental prediction tasks

Key Takeaway

When train and test are different events, feature quality depends on transferability, not just predictive power.

Mechanistic and physically invariant structure often survives event shift better than the fingerprint of a single past event.
